# 사람이 승인하는 일정 등록 에이전트

공지문에서 일정을 추출해 **명확하고 충돌 없는 건은 자동 등록**, 모호하거나 기존 일정과 겹치는 건은 **사람의 검토 후 Google Calendar에 등록**하는 로컬 웹 도구입니다. AIFFEL 「사람이 승인하는 에이전트 만들기」 노드 과제이며, 환불 실습을 일정 등록 업무로 바꾸었습니다. 새 캘린더 앱이나 MCP 서버는 만들지 않습니다.

> **2026-11-10 첫 실연동 실행 확인:** 정상 앱에서 합성 공지 1건·후보 5개를 처리했습니다. 실제 모델 분석/재판정 2회, 최종 등록 3건·반려 2건, 등록 내용의 같은 ID 재조회와 시험 생성물 3건 삭제·부재 확인까지 마쳤습니다. 최종 오류 경계 보완 뒤 오프라인 76개 및 실제 기록 새로고침·390px 화면도 통과했습니다. 검토 조작과 합성 정답 작성자는 에이전트이며, 사용자 독립 평가·일반 정확도·GitHub/LMS 제출 완료를 뜻하지 않습니다. [실행 근거](03_검증/실행결과.json) / [REPORT](REPORT.md).

## 현재 호출 설정

사용자 요청으로 누적 호출 제한을 제거했습니다. 현재 `.env`는 `LLM_CALL_LIMIT=unlimited`이며 내부에서는 임의의 큰 숫자가 아닌 `None`으로 처리합니다. 화면에는 **호출 제한 없음**이 표시됩니다. 사용 이력·승인 대기·기존 일정·인증은 지우지 않았습니다. 앱에서 걸던 누적 횟수 제한만 제거한 것으로 OpenAI의 요금·서비스 한도와는 별개입니다. [적용/실제 화면/81개 검사 근거](03_검증/호출제한해제.json).

## 종료 정보가 없는 일정

사용자 기본 규칙으로 **시간 일정은 시작 시각부터 1시간**, **종일 일정은 시작일 당일**을 적용합니다. 원문에 명시된 종료값은 유지하며, 시작 날짜/시각을 임의로 만들지 않습니다. 적용 결과는 승인 전에 표시하고 원래 누락값과 함께 이력에 보존합니다. 기존 문제 대기 건에도 기본값을 저장하여 종료 정보를 다시 입력하지 않고 승인할 수 있습니다. 다른 모호함·충돌 검토는 유지합니다. [118개 검사·실제 저장/화면 근거](03_검증/종료기본값수정.json).

## 상대 날짜 처리

공지 기준 날짜를 사용해 **오늘·내일·모레를 코드로 계산**합니다. 기준일이 `2026-11-10`이면 내일은 `2026-11-11`입니다. 모델이 누락한 날짜도 원문 인용 근거가 명확하면 보완합니다. ‘내일부터’의 날짜 계산은 시작 날짜만 확정합니다. 종료 정보 누락은 위 사용자 기본 규칙으로 별도 보완하며 원문의 종료값이었다고 표시하지 않습니다. 시간·제목 근거·충돌이 해결되지 않으면 검토를 유지합니다. 기존 문제 대기 건도 날짜만 정정했고 자동 등록하지 않았습니다. [상대 날짜 계산·실제 저장/화면·101개 검사 근거](03_검증/상대날짜수정.json).

## Windows에서 실행

프로젝트 루트에서 **PowerShell**로 실행합니다. 검증 환경은 Python 3.12.10과 `uv`입니다. 이미 `.venv`와 `.env`가 있으면 생성·설치를 생략합니다. 이미 8501에서 실행 중이라면 재기동하지 말고 아래 주소를 여세요.

```powershell
uv venv .venv --python 3.12.10
uv pip install --python .\.venv\Scripts\python.exe -r .\02_구현\의존성_잠금.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
.\.venv\Scripts\python.exe -I -X utf8 -m streamlit run .\02_구현\앱.py --server.address 127.0.0.1 --server.port 8501 --server.headless true --browser.gatherUsageStats false --server.enableCORS true --server.enableXsrfProtection true
```

브라우저에서 `http://127.0.0.1:8501/`을 엽니다. 서버 실행은 로컬 DB를 생성할 수 있습니다. 위 직접 실행을 끝낼 때는 실행한 콘솔에서 `Ctrl+C`를 누릅니다. 다른 PC에 공개하는 호스팅 방법은 포함하지 않습니다.

### 프로젝트 `.env`

앱은 **이 프로젝트의 `.env`만** 읽으며 상속된 다른 프로젝트의 키를 대신 사용하지 않습니다. 실제 값은 사용자가 로컬 편집기로 입력하고 채팅·스크린샷·Git에 넣지 않습니다.

| 변수명 | 용도 / 안전한 기본 설정 |
|---|---|
| `OPENAI_API_KEY` | 사용자가 입력하는 OpenAI API 키. 값을 문서에 기재하지 않음 |
| `OPENAI_MODEL` | `gpt-5.6-luna` 고정 |
| `GOOGLE_CLIENT_FILE` | `비공개/구글_클라이언트.json` |
| `GOOGLE_TOKEN_FILE` | `비공개/구글_토큰.json` |
| `GOOGLE_CALENDAR_ID` | 이번 사용 대상은 개인 기본 캘린더 `primary`. 빈 값에서는 자동 선택하지 않음 |
| `APP_TIMEZONE` | `Asia/Seoul` |
| `DATA_DIR` | `data` |
| `LLM_CALL_LIMIT` | 기본 `unlimited`: 누적 제한 없음. 내부 값은 `None`. 정수를 명시하면 해당 누적 상한을 적용하는 기존 검사 모드 |
| `LLM_MAX_INPUT_CHARS` | 기본 12000자 |
| `LLM_MAX_OUTPUT_TOKENS` | 기본 2500 |
| `MAX_REJUDGEMENTS` | 후보별 재판정 상한, 기본 2회 |

현재 사용 횟수는 표시·기록만 하고 누적 제한으로 막지 않습니다. 유한 정수 상한을 명시한 경우에만 장부의 누적 시도 횟수와 비교합니다. 실패·응답 불명도 기록하며 SDK 자동 재시도는 끕니다. 설정을 바꾼 뒤에는 연결 준비 탭의 **설정 다시 불러오기**를 사용합니다. 코드 변경 직후 이전 모듈이 남은 설정 오류에는 해당 앱 서버를 재기동해야 할 수 있으며, 기록 초기화나 재로그인으로 해결하지 않습니다.

### Google 준비

1. Google Calendar API를 사용할 수 있는 Google Cloud 프로젝트에 **Desktop app OAuth 클라이언트**를 준비합니다. 다른 앱의 인증 자료를 복사하지 않습니다.
2. 다운로드한 클라이언트 JSON을 위 `GOOGLE_CLIENT_FILE` 위치에 보관합니다. `비공개/` 전체는 공유하지 않습니다.
3. 연결 준비 탭에서 **Google 계정 연결**을 눌러 공식 브라우저 로그인·동의를 완료합니다. 앱이 토큰을 `GOOGLE_TOKEN_FILE`에 저장합니다.
4. 저장 후에는 **Google 로그인 정보가 저장되어 있습니다.**와 **Google 계정 다시 연결**이 표시됩니다. 저장 안내는 토큰의 계속된 유효성이나 Calendar API 접근 성공을 보장하지 않습니다. 정상 새로고침은 로그인을 반복하지 않습니다.

요청 권한은 소유 일정 접근 `calendar.events.owned`, 가용 시간 조회 `calendar.events.freebusy`입니다. 충돌 조회에는 시간 구간만 사용하고 기존 일정 제목·본문을 모델에 보내지 않습니다. 인증 자료를 처음 읽을 때 만료돼 있으면 기존 갱신 권한으로 token endpoint를 한 번 요청하고, 성공한 자료만 원자적으로 저장합니다. 실패 시 기존 파일을 보존하며 브라우저 로그인을 자동으로 열지 않습니다. 이 초기 갱신 경로의 성공/실패·1회 제한을 대역 검사했고 실제 Calendar 읽기도 확인했습니다.

## 사용 흐름과 네 응답

1. **새 공지**: 공지 원문과 공지 기준 날짜를 입력하고 **분석하고 일정 등록**을 누릅니다. 이 버튼은 단순 미리보기가 아니며, 자동 기준을 통과하면 실제 `primary` 캘린더에 등록합니다.
2. **자동 처리**: 일시 유효성·원문 근거·충돌 검사를 통과한 후보만 실행합니다. 자동 시간 일정은 명시적 연도·한 날짜·시작/종료 시각을 보수적으로 확인합니다. 명시적 종일 날짜 범위도 지원합니다.
3. **승인 대기**: 정보 부족·모호함·지원하지 않는 근거·시간 충돌이 있으면 외부 쓰기 전에 멈춥니다. 원문, 후보, 인용 근거, 멈춘 이유, 충돌 시간, 승인 시 생성될 일정을 확인합니다.

| 응답 | 동작 |
|---|---|
| 승인 | 현재 후보로 진행. 유효하지 않은 일시는 단순 승인 불가 |
| 수정 후 승인 | 제목·일시·종일 여부·장소를 수정하고 유효성·충돌을 다시 검사 |
| 반려 | 사유를 남기고 종료. Google 일정 미생성 |
| 다시 판정 | 지시를 입력해 해당 후보만 모델에 다시 요청하고 기준 재검사. 호출 예산과 후보별 상한 적용 |

승인 직전 새 충돌이 생기면 다시 검토를 요구합니다. 수정·재판정으로 바뀐 버전에는 예전 승인을 재사용하지 않습니다. `review` 노드의 `interrupt()`와 Google 쓰기 `execute` 노드를 분리했습니다.

## 저장과 결과 불명 안전장치

- `data/업무.sqlite`: 후보·원문·결정 이력·모델 호출·전송 장부. `data/체크포인트.sqlite`: LangGraph 실행 상태. 후보별 `thread_id`로 대기 건을 구분합니다.
- DB를 유지하면 재시작 후 대기 건을 복원합니다. 체크포인트가 빠진 대기 건은 자동 전송 대신 다시 검토합니다. 실제 서버 종료·재기동 후 대기 4건의 ID·버전·상태와 호출 장부가 보존되는 것을 정상 앱에서 확인했습니다.
- Google 생성 뒤 **같은 ID 재조회와 내용 일치**까지 확인해야 `created`입니다. 응답 유실·조회 실패·내용 불일치는 `unknown`으로 보존합니다.
- 처리 기록의 **등록 상태 확인**(`reconcile`)은 같은 ID만 조회하며 새 일정을 만들지 않습니다. `unknown`을 실패로 간주해 같은 공지를 다시 분석하지 마세요. 안정적인 ID·전송 장부는 중복 위험을 줄이지만 절대 무중복을 보장하지 않습니다.

## 오프라인 테스트 재현

프로젝트 루트의 PowerShell에서 실행합니다. 한국어 파일명을 놓칠 수 있는 단순 `unittest discover` 대신 제공 실행기를 사용합니다. `-I`는 상속 `PYTHONPATH` 혼입을 막고, `runpy` 앞에서 구현 경로를 명시합니다.

```powershell
.\.venv\Scripts\python.exe -I -X utf8 -c "import sys,runpy; from pathlib import Path; p=Path('02_구현').resolve(); sys.path.insert(0,str(p)); runpy.run_path(str(p/'테스트실행.py'),run_name='__main__')"
```

실행기는 테스트 수·고유 식별자·실행 전후 소스 해시를 검사하고 `.local/최근_테스트.json`에 결과를 저장합니다. 외부 제공자는 대역이며 서버·브라우저·실계정 호출을 실행하지 않습니다. 현재 백엔드 62개 + 화면 20개 + 상대 날짜 11개 + 종료 기본값 8개 + 소비자 통합 15개 + 평가 2개, 총 **118개 통과**(실패·오류·skip 0)입니다. [현재 종료 기본값 수정 검사](03_검증/종료기본값수정.json)에 118개 고유 시험과 소스 해시를 담았습니다. [상대 날짜 수정 검사](03_검증/상대날짜수정.json)의 101개 기록도 보존했습니다. [이전 호출 제한 해제 검사](03_검증/호출제한해제.json)의 81개 기록도 보존했습니다. [이전 76개 회귀 기록](03_검증/회귀검사.json)은 앞선 실연동 검증 시점의 원본으로 보존했습니다.

## 승인 기준 비교 재현

최종 정적 검토의 CAL-03(잘못된 외부 응답의 오류 경계 이탈)은 실제 SDK 대역으로 재현·수정했습니다. null 응답·잘못된 오류 메타데이터·가용 시간 응답을 안전한 공개 오류로 바꾸고, 재판정 실패 기록과 호출 예산을 보존합니다. 보완 후 실제 Google 읽기·정상 서비스 재조립·실제 화면을 다시 확인했습니다. 실제 모델 2회와 생성 3건은 앞선 정상 실연동 근거이며 새 유료 요청·일정을 추가하지 않았습니다. [원 판정과 조치 구분](03_검증/검토조치.json).

아래 명령은 모델·Google을 호출하지 않고 같은 고정 자료에 네 기준을 적용합니다. 기존 Google 일정을 추가 생성하거나 안전 가드를 끄지 않습니다.

```powershell
.\.venv\Scripts\python.exe -I -X utf8 -c "import sys,runpy; from pathlib import Path; p=Path('02_구현').resolve(); sys.path.insert(0,str(p)); runpy.run_path(str(p/'평가실행.py'),run_name='__main__')"
```

- 입력: [평가자료.json](03_검증/평가자료.json), 실제 추출 5후보와 최초 위험 코드·에이전트 시나리오 기대값.
- 출력: [평가결과.json](03_검증/평가결과.json). A만/B만/A 또는 B/전부 검토의 개입률·놓침·헛멈춤.
- 작은 합성 표본의 정책 비교입니다. 사용자 독립 라벨, 일반 업무 정확도나 미공개 평가 성능이 아닙니다.
- 실제 등록 3건은 내용 확인 뒤 시험 소유 ID만 삭제했습니다. 처리 기록의 ‘등록 완료’는 당시 생성 확인 이력이며 지금 Google 이벤트가 남아 있다는 뜻은 아닙니다. DB·호출 예산은 지우지 않았습니다.

## 공개 제외와 한계

- `.env`, 인증 JSON·토큰, `비공개/`, `.venv/`, `data/`, `.local/`, 로그·DB·캐시를 제외합니다. `.env.example`만 안전한 변수 예시로 공유합니다. 공유 저장소에는 개인 원문·실제 일정 ID·계정 정보가 포함된 원시 증거를 넣지 않습니다.
- **로컬 실행이지 완전한 오프라인 처리는 아닙니다.** 공지·기준 날짜·시간대는 OpenAI로, 등록 일정은 Google로 전송됩니다. 재판정에는 현재 후보·추가 지시도 전송됩니다.
- 단일 사용자·단일 프로세스용입니다. 다중 사용자 인증·권한 분리·인터넷 공개 운영은 지원 범위가 아닙니다.
- 기준일로 계산하는 오늘·내일·모레의 단일 날짜는 지원합니다. 시작만 명시한 ‘내일부터’·이번/다음 주·복합 상대 범위·연도 생략·알려진 반복·교차일 시간 일정은 검토합니다. 자연어 전체의 의미·반복 탐지·프롬프트 인젝션 방어를 보장하지 않습니다.
- 기존 Google 일정 수정·삭제, 참석자 초대·알림 발송, 메일·메신저 자동 수집, 월간 캘린더 UI는 제외합니다. 오래된 대기 건의 자동 승인·반려·에스컬레이션 정책도 미정입니다.
- 실제 모델·Calendar·네 결정·대기 복원은 합성 시험에서 확인했습니다. 일반 자연어 정확도·실제 업무 자료의 오류율·사용자 판단 속도·사용자 회고·GitHub/LMS 제출은 별도입니다. 390px에서 큰 제목 끝 한 글자가 다음 줄로 넘어가는 조판 한계도 남아 있습니다.
