# 사람이 승인하는 일정 등록 에이전트 작업 명세서

> 작성일: 2026-11-09 (Asia/Seoul)
> 상태: 사용자 후속 요청의 누적 호출 제한 제거와 상대 날짜 계산 수정을 적용하고 101개·실제 저장/화면을 확인했습니다. 아래 초기 실제 모델 분석·재판정, 자동/승인/수정 후 재검토·승인/반려, 대기 재시작 복원, Google 생성 3건 내용 재조회·정리, 합성 기준 비교·실제 화면을 확인했습니다. 최종 독립 지적 CAL-03은 부모가 재현·수정·검증했으며 코드·문서의 로컬 기록 상태는 Git·진행 현황·인계 영수증을 대조합니다. 사용자 선택 이유·회고·공개/LMS 제출은 미완료이며 실행 증거와 구분합니다.

## 1. 목표

공지문을 입력하면 AI가 일정 정보를 추출하고, 계산 가능한 위험 기준에 해당하는 건만 사람에게 확인받은 뒤 Google Calendar에 등록하는 과제입니다.

새 캘린더 앱을 만드는 것이 아닙니다. 과제의 웹 화면은 공지 입력·검토·처리 기록을 담당하며, 최종 일정의 저장 대상은 실제 Google Calendar입니다. 로컬 DB 등록이나 가짜 성공 화면을 Google Calendar 연동 성공으로 대신하지 않습니다.

분류: 노드 과제·실습. 기준 노드: `에이전트 팀 꾸리기_Agt2 / 9.사람이 승인하는 에이전트 만들기 [프로젝트]`.

기술 명세서·앱/테스트·전용 환경·서버 유지에 이어 사용자가 평소 캘린더와 키 입력을 확인하고 제한된 실제 시험을 승인했습니다. 실제 범위의 정본은 `.local/실연동검증/범위.json`입니다. 기존 개인 일정·다른 인증 자료·프로젝트 공통 설정 변경은 여전히 제외합니다. 신규 클라이언트 생성·사용자 로그인·실제 API 성공을 각각 구분하며 공개·push는 승인에 포함되지 않습니다.

현재 운영 변경: 사용자 원문 “호출 제한 없애 그냥;”에 따라 누적 호출 상한을 제거했습니다. 실제 설정은 `unlimited`, 내부는 `None`이며 임의로 큰 숫자를 쓰지 않습니다. 기존 업무/호출/전송·인증 기록과 HITL 규칙은 유지합니다. 변경 검증에 추가 유료 요청이나 일정 생성/삭제는 하지 않았습니다. 초기 시험의 3회 한도는 과거 실행 범위이지 현재 사용 제한이 아닙니다.

현재 날짜 처리 변경: 공지 기준일에서 오늘·내일·모레를 계산하고 원문 인용 근거를 검증합니다. 모델에 없는 날짜를 임의로 찍는 것이 아니라 명시 상대 표현을 계산하는 방식입니다. 실제 문제 건은 시작 전용 내일부터였으므로 시작 날짜만 2026-11-11로 보완했고 종료 정보 미정·검토 상태를 유지했습니다. 다른 작업/장부/체크포인트/인증은 보존했으며 모델·Calendar 요청 없이 실제 화면을 확인했습니다. 이전 상대 날짜 미지원 서술은 초기 구현 기록입니다.

## 3. 사용자 흐름

1. 사용자가 공지 원문과 날짜 해석의 기준 정보를 입력합니다.
2. AI가 일정 후보와 원문 근거를 추출합니다. AI는 날짜나 필수 정보를 임의로 확정하지 않습니다.
3. 코드가 필수 정보·날짜의 유효성·승인 기준을 검사합니다.
4. 기준에 해당하지 않는 유효한 건은 지정된 Google Calendar에 자동 등록합니다.
5. 기준에 해당하는 건은 등록 전에 멈추고 대기 상태를 저장합니다.
6. 사람이 원문·일정 후보·근거·멈춘 이유·등록 시 결과를 보고 결정합니다.
7. 승인 또는 수정 후 승인된 건만 해당 내용으로 등록하고, 반려된 건은 등록하지 않습니다.
8. 실제 생성된 일정의 ID로 재조회하고, 승인 내용과 저장된 제목·날짜·시간 등이 일치하는지 확인합니다.

자동 처리 경로는 제품의 요구사항입니다. 개발 중 첫 실등록 시험의 별도 승인은 제품에서 모든 일정을 사람이 승인하도록 바꾸는 근거가 아닙니다.

## 5. 첫 버전 구현 기준 — 평가 정답과 선택 이유는 사용자 작성 대기

| 후보 | 계산 가능한 형태로 구체화할 방향 | 막으려는 위험 |
|---|---|---|
| A. 일시 정보 부족·모호함 | 원문 근거 없는 날짜·시각, 필수 정보 누락 등 명시적 검증 결과가 존재하면 검토 요청 | AI가 추측한 일시에 등록 |
| B. 기존 일정과 시간 충돌 | 승인된 조회 범위의 기존 일정과 후보의 시간 구간이 겹치면 검토 요청 | 이미 예정된 일과 중복 예약 |

위 두 기준을 첫 버전의 구현 기본값으로 사용했습니다. 자동 시간 일정은 명시적 연도·한 날짜·시작/종료 시각의 근거가 맞는 경우로 제한하고, 다일 종일 구간은 종일이 명시된 경우 처리합니다. 후속 수정으로 기준일을 이용한 오늘·내일·모레의 단일 날짜를 지원합니다. 시작만 지정한 내일부터·이번/다음 주·복합 상대 범위·연도 생략·알려진 반복·교차일 시간 후보는 검토로 보냅니다. 이는 코드와 합성 사례에서 검증한 범위이며 실제 모델·업무 자료의 정확도를 보장하지 않습니다.

검증 정답은 모델 자신의 확신도와 별도로 정합니다. 현재 `03_검증/평가자료.json` v1은 실제 추출 5후보와 최초 위험 코드를 고정하고 에이전트가 합성 시나리오 기대값을 부여한 자료입니다. 같은 자료에 A만/B만/A 또는 B/전부 검토를 적용해 지표를 계산했습니다. 사용자 독립 라벨·미공개 평가·일반 업무 정확도로 주장하지 않으며 사용자 판단은 작성 대기로 구분합니다.

- 개입률: 전체 중 사람 검토 대상으로 보낸 비율.
- 놓침: 사람이 봐야 하는데 자동 처리한 건수.
- 헛멈춤: 자동 처리해도 되는 건을 검토 대상으로 보낸 건수.

유효하지 않은 일정은 단순 승인만으로 등록하지 않으며, 필요한 정보 수정 후 다시 유효성을 확인합니다.

## 6. 승인 응답과 상태 보존

강의 4강은 승인·수정 후 승인·반려·다시 판정의 네 응답과 후속 처리를 설명합니다. 프로젝트 필수 구현 문구는 승인이나 반려 같은 답을 받을 수 있어야 한다고 표현합니다. 이 과제는 네 응답과 후보별 재판정 최대 2회를 첫 구현 기본값으로 사용했습니다. 최소 제출 문구·강의 권장 설계·실제 구현 선택은 구분합니다.

대기 상태는 메모리만이 아니라 파일 또는 DB에 남겨 재시작 후 복원할 수 있도록 설계합니다. 대기 시간 초과 시 자동 승인할지 등 운영 정책은 아직 미정입니다.

LangGraph의 재개 시 중단된 노드가 처음부터 다시 실행될 수 있습니다. 일정 생성 같은 외부 변경을 승인 노드의 `interrupt()` 앞에 두지 않고 별도 실행 단계로 분리합니다. 중복 클릭·응답 유실·재시도에 따른 중복 등록도 설계·검증 대상입니다.

## 7. 첫 버전의 경계

- 별도 캘린더 앱, MCP 서버, 공개 호스팅은 이번 제안 범위에서 제외합니다.
- 공지 입력은 직접 붙여넣기를 시작점으로 제안합니다. 메일·메신저 자동 수집은 현재 합의 범위가 아닙니다.
- 기존 Google 일정의 임의 수정·삭제, 참석자 초대·외부 알림 발송은 현재 승인 범위가 아닙니다.
- 실제 시험은 사용자 승인한 `primary`와 2030-01-10 합성 공지 1건, 누적 모델 3회·생성 최대 5건·이번 ID만 정리하는 범위를 사용했습니다. 생성 3건은 내용 재조회 후 삭제·부재 확인했고 기존 일정은 변경하지 않았습니다.
- 일정 추출에는 `gpt-5.6-luna`를 사용합니다. 사용자 API 키와 앱 누적 상한을 유지하며 다른 모델이나 로컬 LLM으로 임의 대체하지 않습니다. 실제 사용 2회는 계정의 무료 적용/청구액 증거가 아닙니다.
- 인증값은 코드·문서·로그·Git에 넣지 않습니다. 인증 JSON·토큰은 승인된 `비공개/`, OpenAI 키는 `.env`에 보관하며 Git 제외를 확인합니다. 다른 프로젝트 인증 자료를 읽거나 복사하지 않습니다.

| 웹 데모와 제출물의 완결성 | R5, R6, R8 | 실제 승인 화면 사용, 구조도·기준·실행 결과가 있는 보고서 |

| HITL 파이프라인 구현의 정확성 | R1, R2, R4 | 외부 반영 전 멈춤·재개, 자동 처리 경로, 대기 보존 |

`REPORT.md`의 원문 요구 항목은 주제와 이유, 파이프라인 구조도, 승인 기준과 이유, 실행 결과, 데모 화면 설계와 캡처, 프로젝트 회고입니다. 구조도는 Mermaid 또는 이미지로 작성할 수 있습니다. 회고·기준 선택 이유 등 사용자 판단은 사용자 작성과 에이전트 사실 기록을 구분하며 임의로 사용자 의견을 만들어 넣지 않습니다.

LMS 프로젝트 안내는 GitHub 저장소 주소 제출을 요구합니다. 별도 제출 화면에는 파일 또는 URL 한 가지 방식만 가능하며 제출 후 수정할 수 없다는 안내가 있습니다. 제출 버튼은 사용자가 최종 확인합니다.

## 9. 외부 모델 선택과 Google 연동 준비

### 확정 모델 — `gpt-5.6-luna`

사용자가 ‘5.6 루너’를 선택했고, 공식 모델 페이지의 API 모델 ID `gpt-5.6-luna`와 일치함을 확인했습니다. 다른 제품의 별칭이나 접미사를 붙여 모델 ID를 바꾸지 않습니다.[12]

- 공식 문서에서 Structured Outputs·함수 호출 지원을 확인했습니다. 표준 텍스트 요금은 100만 토큰당 입력 USD 0.20, 출력 USD 1.20입니다. 계정 접근과 실제 추출 품질은 아직 미검증입니다.[12]
- 같은 단순 계산 조건인 요청당 입력 2,000토큰·청구되는 출력 500토큰, 총 100회, 캐시·재시도·추가 도구 없음이면 USD 0.10입니다. Python Decimal 계산 예시이지 실제 사용량·청구액이나 승인된 호출 예산이 아닙니다.[12]
- 데이터 공유 혜택의 대상 모델 목록과 실제 계정 적용은 별개입니다. 사용자 계정의 공유 활성화·잔액·사용량은 조회하지 않았고, 모델 선택을 무료 혜택 적용 또는 실호출 승인으로 기록하지 않습니다.[6]

### 선택 전 비교 자료 — 2026-11-09, 현재 선택을 대체하지 않음

| 후보 | 표준 입력 요금 / 100만 토큰 | 표준 출력 요금 / 100만 토큰 | 공식 지원과 한계 |
|---|---:|---:|---|
| OpenAI `gpt-6-luna` | USD 0.10 | USD 0.50 | Structured Outputs와 함수 호출 지원. 현재 계정의 접근·실제 추출 품질은 미검증.[2][3] |
| Google `gemini-3.5-flash-lite` | USD 0.30 | USD 2.50 | 안정 버전과 Structured Outputs 지원. 현재 계정의 접근·실제 추출 품질은 미검증.[4][5] |

초기에는 `gpt-6-luna`를 권고했지만 사용자의 `gpt-5.6-luna` 선택으로 대체되었습니다. 아래 비교 비용은 선택하지 않은 두 후보의 과거 검토 기록이며 현재 모델의 비용으로 사용하지 않습니다.

계산 예시: 요청마다 입력 2,000토큰·청구되는 출력 500토큰, 총 100회, 캐시·재시도·추가 도구 없이 표준 요금으로 계산하면 각각 USD 0.045, USD 0.185입니다. Python Decimal로 계산했으며 실제 사용량·예산 승인·청구액이 아닙니다. 실제 프롬프트·응답·재판정 호출이 정해지면 다시 산정합니다.[2][3][5]

- OpenAI의 데이터 공유 무료 토큰 안내는 기존 `📝 2026-11-05 데이터 공유 무료 토큰 안내.md`를 읽었습니다. 당일 도움말 직접 GET은 HTTP 403이었고, 공식 검색 결과 발췌에서 대상 모델 그룹을 재확인한 수준입니다. 계정의 등록·잔액·혜택 적용은 조회하지 않았으며, 공유 설정도 변경하지 않았습니다. 무료 적용을 전제로 모델이나 예산을 확정하지 않습니다.[6]
- Gemini 가격표에는 무료 티어가 있으나 해당 트래픽의 제품 개선 활용과 별도 한도가 있습니다. 사용자 계정의 실제 무료 이용 가능 여부는 미확인입니다.[5]
- 외부 모델 사용 시 공지문이 해당 제공자에게 전송됩니다. 현재 권고는 공지 원문·기준 날짜·시간대만 추출 모델에 보내고, 기존 캘린더 상세는 보내지 않은 채 코드가 충돌을 확인하는 방식입니다. 최종 전송 범위는 기술 설계에서 확정합니다.

### Google 설정 — 기존 옵시디안 프로젝트와 새 클라이언트

처음에는 준비 여부를 모른다고 답했으나, 이후 기존 ‘옵시디안’ Google Cloud 프로젝트를 사용하고 OAuth 클라이언트를 새로 만들기로 선택했습니다. 기존 옵시디안 프로젝트의 인증 정보나 클라이언트를 재사용·수정하라는 승인은 아닙니다.

1. Cloud Console에서 기존 옵시디안 프로젝트가 정확한 대상인지 확인합니다. 표시 이름만으로 프로젝트 ID를 추측하지 않습니다.
2. Calendar API 활성화 상태를 읽기 전용으로 확인합니다. 비활성 상태이면 활성화 범위를 별도로 확인합니다.
3. 공식 로컬 Python 인증 절차는 `Google Auth platform → Clients → Create Client → Desktop app`입니다. 과제 클라이언트의 제안 이름은 `일정 등록 에이전트`입니다.[1]
4. 생성 화면의 `Use this client for an AI-powered agent` 도움말은 Google MCP 용도에 대한 선택이라고 안내했습니다. 이번 앱은 직접 Calendar API를 사용하므로 선택하지 않았습니다. 일반 AI 활용이라는 이름만 보고 선택하지 않습니다.[1]
5. 인증 JSON·토큰은 사용자가 선택한 과제의 `비공개/`에 보관하고, 기존 클라이언트·프로젝트 공통 동의 화면을 변경하지 않습니다. 신규 클라이언트 생성, 파일 저장, 로그인 성공, Calendar API 실호출은 별개 상태로 기록합니다.
6. 프로젝트·API·클라이언트 유형 등 비밀이 아닌 상태만 공유합니다. 비밀번호·키·토큰·인증 JSON은 채팅으로 받지 않습니다.

- Google Calendar Python quickstart: Google Cloud 프로젝트·API 활성화·OAuth 클라이언트와 사용자 인증의 준비 절차. 공식 본문 HTTP 200 확인.[1]

- Google Calendar 인증 범위: 본인 소유 일정·앱 생성 캘린더·가용 시간 등 권한 범위가 구분됨. 실제 요청할 권한은 미정. 공식 본문 HTTP 200 확인.[8]
