## 1. 선택한 구조와 경계

한 사용자가 자기 PC에서 여는 웹 도구입니다. 별도 캘린더 앱이나 MCP 서버를 만들지 않습니다.

- UI: Streamlit의 표준 입력·폼·탭. 새 공지, 승인 대기, 처리 기록, 연결 준비를 구분합니다. 폼은 묶음 제출하고 렌더링·새로고침만으로 처리 요청을 보내지 않습니다.[15]
- 처리: Python 서비스와 LangGraph. AI는 일정 후보를 제안하며 코드가 검증·분기·승인·외부 반영을 관리합니다.
- 영속 상태: SQLite 기반 LangGraph 체크포인터, 별도 업무/전송/모델 호출 장부. 메모리 저장만으로 대기 건을 보관하지 않습니다.[9][14]
- 외부 AI: OpenAI API `gpt-5.6-luna`. 다른 모델로 자동 대체하지 않습니다.[12]
- 캘린더: 사용자가 선택한 기존 Google Calendar. Google Cloud의 기존 옵시디안 프로젝트에 신규 과제용 OAuth 클라이언트를 사용합니다. 기존 클라이언트·공통 동의 화면은 임의 변경하지 않습니다.
- 실행 대상: 설치된 Python 3.12.10으로 만드는 프로젝트 전용 `.venv`입니다. 사용자가 생성·설치를 승인했습니다. 기존 Hermes Python이나 다른 프로젝트 환경에는 설치하지 않습니다.

순수 HTML만으로 만들면 비밀값을 브라우저에 전달하거나 중단 상태를 별도로 관리해야 합니다. FastAPI와 별도 JS 프런트엔드는 가능하지만 이번 과제에서는 서버·화면 연결 코드가 더 늘어납니다. 작은 단일 사용자 승인 도구에는 Streamlit을 선택해 외부 반영과 상태 보존에 집중합니다. 정교한 캘린더 편집 UI나 다중 사용자 서비스는 현재 목표가 아닙니다.

## 2. 모듈과 파일 소유

`02_구현/일정도우미/`는 Python 패키지이며 코드 내부 폴더에는 번호를 추가하지 않습니다. 새 코드 파일은 한국어 이름을 쓰고 `__init__.py` 같은 언어 필수 이름은 유지합니다.

## 3. 처리 흐름

1. 웹 폼에서 공지와 공지의 기준 날짜를 받습니다. 기준 날짜는 원문을 해석하는 기준이며 일정 날짜로 자동 복사하지 않습니다.
2. 준비 상태와 Google 연결의 명시적 오류를 먼저 검사해, 준비되지 않은 상태에서 유료 추출부터 실행하지 않습니다.
3. 모델에 공지·기준 날짜·시간대만 전달하여 일정 후보 목록을 추출합니다. 기존 일정 상세를 LLM에 보내지 않습니다.
4. 각 후보를 독립 작업과 `thread_id`로 저장하고 LangGraph를 실행합니다. 같은 공지의 여러 일정도 각각 승인·반려할 수 있습니다.
5. 명확하고 충돌 없는 유효 후보는 Google에 자동 등록합니다. 검토가 필요한 후보만 `interrupt()`로 대기합니다.
6. `Command(resume=...)`으로 한 작업의 응답을 전달합니다. 수정·반려·재판정은 다른 작업의 내용을 바꾸지 않습니다.[9]
7. 외부 실행은 승인 노드와 분리합니다. 실제 요청과 승인된 후보를 같은 버전/해시로 묶고 등록 후 ID로 재조회합니다.

기준 날짜와 시간대의 초기값은 UI에 명시합니다. 과거 공지는 사용자가 기준 날짜를 바꿔야 합니다. 초기 구현의 입력 상한은 12,000자, 추출 후보 상한은 5개, 후보별 재판정 상한은 2회로 설계합니다. 상한 초과는 조용히 자르지 않고 설명합니다. 이 수치는 교안 고정값이나 검증된 성능값이 아니라 작은 첫 버전의 구현 기본값입니다.

## 4. 일정 후보와 승인 기준

### EventDraft

JSON 객체의 필드:

- `title: str`
- `start_date: str | null`, `end_date: str | null` — `YYYY-MM-DD`
- `start_time: str | null`, `end_time: str | null` — `HH:MM`
- `all_day: bool`
- `location: str`
- `evidence: list[str]` — 공지에 실제로 존재하는 인용문
- `ambiguities: list[str]` — 모델이 표시한 모호함. 이 목록이 비었다고 정확성을 보장하지 않음

모델 출력 형식과 날짜 의미의 정확성은 별개입니다. 인용문이 원문에 있다는 검사만으로 날짜의 의미가 맞다고 판정하지 않습니다. 자동 처리의 날짜/시각 근거는 코드가 지원하는 명시적 날짜·시간 표현으로 추가 확인하고, 지원하지 않는 표현은 사람 검토로 보냅니다. 상대 날짜 지원 범위도 규칙 테스트로 고정합니다. 범위를 넓혀 자연어 전체의 정확성을 보장하지 않습니다.

자동 시간 일정의 허용 형태는 같은 날짜 안의 명시적 시간 범위로 고정합니다. 종일이 명시된 날짜 범위는 별도로 허용합니다. 알려진 명시 반복 표현은 검토로 보내고, 반복 단어가 없어도 날짜를 넘는 시간 후보는 단일 연속 일정으로 자동 해석하지 않습니다. 사람이 유효한 일시를 명시적으로 수정·승인하는 경로는 유지합니다. 보수적인 표현 검사는 헛멈춤이 있을 수 있으며 모든 자연어 반복 탐지를 보장하지 않습니다.

### 계산 가능한 기준

| 기준 | 조건 | 처리 |
|---|---|---|
| A. 정보 부족·근거 불명확 | 필수 일시 누락, 원문 인용 불일치, 코드가 확인하지 못한 시간 근거, 모델의 명시적 모호함 등 | 사람 검토. 잘못된 일시 자체는 수정 전 등록 불가 |
| B. 시간 충돌 | 후보 구간과 조회한 busy 구간이 `start < other_end` 및 `end > other_start`를 만족 | 사람 검토. 맞닿기만 한 경계는 겹침으로 세지 않음 |

수정 후 승인에서는 사용자가 지정한 일시가 원문 추출과 다를 수 있습니다. 이를 사용자 수정으로 기록하고, 유효한 일시·충돌 재확인·버전 확인을 건너뛰지 않습니다. 승인 직전에 새 충돌이 생기면 새 검토 사유를 표시합니다. 이미 보여 준 충돌을 알고 승인한 경우와 새로운 충돌을 구분합니다.

종일 일정의 UI `end_date`는 마지막 포함 날짜로 정의합니다. Google의 종료는 배타적이므로 전송 때 그 다음 날짜로 변환합니다. 시간 일정의 종료 시각도 Google 계약대로 처리합니다.[7]

공지는 등록 요청의 자료일 뿐 도구 실행 지시가 아닙니다. 본문에 ‘승인 없이 보내라’ 같은 문장이 있어도 키·모델·권한·호출 한도·승인 상태를 바꿀 수 없습니다.

## 5. 공개 서비스 계약 — 화면/백엔드 연결 정본

공개 모듈: `일정도우미.서비스`

- `build_service(project_root: Path) -> CalendarAgentService`
- `CalendarAgentService.readiness() -> dict`
- `CalendarAgentService.analyse(text: str, reference_date: str) -> list[dict]`
- `CalendarAgentService.list_jobs() -> list[dict]`
- `CalendarAgentService.get_job(job_id: str) -> dict`
- `CalendarAgentService.decide(job_id: str, expected_version: int, action: str, edits: dict | None = None, reason: str = "", instruction: str = "") -> dict`
- `CalendarAgentService.reconcile(job_id: str, expected_version: int) -> dict`
- `CalendarAgentService.connect_google() -> dict`
- `CalendarAgentService.close() -> None`
- `ServiceError`는 `.code: str`, `.message: str`를 가진 공개 오류입니다. 메시지에 키·토큰·공급자 원시 본문을 넣지 않습니다.

`build_service`는 로컬 저장소를 만들 수 있지만 네트워크 요청·로그인·브라우저 열기·모델 호출은 하지 않습니다. 모든 작업 경로는 명시적으로 주입한 프로젝트 안으로 제한합니다. 테스트는 실제 사용자 저장소를 기본 경로로 사용하지 않습니다.

### readiness 필드

`model`, `api_key_set`, `client_file_present`, `token_file_present`, `target_calendar_set`, `llm_calls_used`, `llm_call_limit`, `can_analyse`, `issues: list[str]`.

파일이 있다는 것은 인증 성공이 아닙니다. 화면은 ‘자료 준비’와 ‘실제 연결 확인’을 혼동하지 않습니다. `.env`의 실제 값이나 토큰 내용을 반환하지 않습니다.

### JobView 필드

`id`, `title`, `status`, `version`, `source_text`, `reference_date`, `draft: EventDraft`, `risk_reasons: list[{code,message}]`, `busy_intervals: list[{start,end}]`, `last_error`, `decisions: list[dict]`, `google_event_id: str | null`, `google_event_url: str | null`, `created_at`, `updated_at`, `rejudge_count`.

상태값은 `needs_review`, `created`, `rejected`, `error`, `unknown`을 사용합니다. 내부 실행 중 값이 있더라도 이 공개 상태와 의미가 어긋나지 않게 변환합니다. `unknown`은 등록 요청의 결과를 아직 확정할 수 없다는 뜻이며 ‘실패했으니 다시 만들기’로 취급하지 않습니다.

실제 백엔드의 `last_error`는 `{code, message}` 객체 또는 null입니다. 화면은 공개 `message`만 표시하고 객체 전체나 공급자 내부 상세를 문자열로 덤프하지 않습니다. 실제 소비자 통합에서 이 차이를 재현하고 표시 경로를 보완했습니다.

`action`은 `approve`, `edit_approve`, `reject`, `rejudge`입니다. 반려 사유와 재판정 지시는 비어 있으면 거절합니다. `edits`는 EventDraft의 수정 가능한 필드만 허용합니다. 작업 ID·버전·상태·외부 ID를 클라이언트가 바꿀 수 없습니다.

버전 불일치, 완료된 작업 재승인, 유효하지 않은 수정, 연결/예산 미준비는 실제 전송 전에 `ServiceError`로 거절합니다. 새 작업·승인 기록·모델 호출·Google 쓰기가 발생하지 않았는지도 테스트합니다. 0개 후보는 유효한 분석 결과일 수 있으며 API 실패와 구분합니다.

## 6. 저장·동시성·외부 결과 불명

- 저장 위치는 `data/` 아래의 업무 DB와 체크포인트 DB입니다. 양쪽 모두 Git에서 제외합니다. 키·토큰은 DB에 저장하지 않습니다.
- 서비스는 단일 사용자·단일 프로세스용 동기 모델입니다. 공개 메서드와 공유 DB 연결에 잠금을 적용합니다. 여러 서버의 동시 운영을 지원한다고 주장하지 않습니다.
- 체크포인트에는 중간 실행 상태를, 업무 장부에는 작업 인덱스·사람 결정·모델 요청 예약·전송 시도/결과를 저장합니다. 화면의 전송 결과는 확인된 전송 장부와 일치해야 합니다.
- 모델 호출은 실제 전송 직전에 영속 장부에서 예약하고, SDK 자동 재시도는 끕니다. 타임아웃·결과 불명도 한도를 소비한 시도로 남깁니다. 그래프 재개·페이지 새로고침이 기존 추출을 다시 호출하지 않게 합니다.
- 일정 ID는 앱이 UUID 기반으로 생성한 안정적인 값으로 고정합니다. Google 허용 문자·길이와 맞아야 합니다. Google 문서가 분산 시스템의 충돌 탐지를 보장하지 않으므로 ‘절대 중복 없음’으로 표현하지 않습니다.[7]
- 쓰기 전에 시도·payload 해시를 기록합니다. 성공 응답 후에는 같은 ID로 조회해 내용을 확인합니다. 응답 유실은 `unknown`으로 보관하고, `reconcile`은 기존 ID 조회만 합니다. 확인 버튼이 새 일정을 만들지 않습니다.
- 수정·재판정은 새 후보 버전을 만들고 이전 승인을 무효화합니다. 이미 생성된 Google 일정의 수정·삭제 기능으로 확장하지 않습니다.
- 일시·기록은 UTC ISO 형식으로 저장하고 UI에서 설정 시간대로 표시합니다. 날짜만 있는 종일 일정은 날짜 의미를 보존합니다.

## 7. 실제 외부 연결

### OpenAI

공식 Responses API의 구조화 출력 방식을 사용합니다. 모델은 `gpt-5.6-luna`, 초기 추론 설정은 `reasoning.effort=none`, 표준 서비스 티어, `store=False`, 자동 재시도 0으로 설계합니다. 외부 도구는 연결하지 않습니다. JSON 파싱·필수 필드·길이·참조 관계를 코드로 검증하며 거부·불완전 응답을 정상 일정으로 바꾸지 않습니다.[12][24]

실제 계정 지원은 아직 미검증입니다. 과제 환경에 설치한 OpenAI SDK 3.46.0에서 `model`, `input`, `text`, `reasoning`, `max_output_tokens`, `store`, `service_tier` 인자가 존재함을 확인했습니다. 이후 실제 연결 구현과 전송 대역 시험을 거쳐 실호출합니다. 기존 Hermes의 구독 토큰·다른 프로젝트 키를 사용하지 않습니다.

### Google

로컬 Desktop app OAuth와 사용자가 제공한 신규 클라이언트 JSON을 사용합니다. `connect_google` 버튼을 눌렀을 때만 공식 인증 흐름을 시작합니다. 단순 모듈 import나 화면 조회가 로그인 창을 열지 않습니다.[1]

권한 설계안은 소유 일정 접근 `calendar.events.owned`와 가용 시간 조회 `calendar.events.freebusy`입니다. 실제 권한 부여는 후속 사용자 승인입니다. 캘린더 목록·제목·내용 전체를 추가로 수집하는 권한은 넣지 않습니다.[8][13]

충돌 조회는 `freebusy.query`로 시간 구간만 받아 사용합니다. API가 오류를 내거나 범위 일부가 실패하면 ‘충돌 없음’으로 바꾸지 않습니다.[13]

등록 요청에는 참석자·첨부·회의 링크 생성을 넣지 않으며 알림 옵션을 명시합니다. 일정 생성 권한과 기존 일정 수정·삭제 권한은 앱의 기능 범위에서 구분합니다. 등록 후 조회가 실패하면 확인되지 않은 성공으로 표시하지 않습니다.[7]

## 8. 설정·인증 파일

사용자는 프로젝트 `.env`와 `비공개/` 보관, 빈 설정·예시 파일 준비를 승인했습니다. 실제 값은 사용자 입력으로 남깁니다.

| 변수 | 기본/용도 |
|---|---|
| `OPENAI_API_KEY` | 빈 값. 사용자가 직접 입력 |
| `OPENAI_MODEL` | `gpt-5.6-luna` |
| `GOOGLE_CLIENT_FILE` | `비공개/구글_클라이언트.json` 경로. 실제 다운로드 파일명을 보존하려면 이 경로 설정을 해당 이름으로 지정 |
| `GOOGLE_TOKEN_FILE` | `비공개/구글_토큰.json` 경로 |
| `GOOGLE_CALENDAR_ID` | 빈 값. 사용자가 대상 캘린더를 선택하기 전 기본 캘린더에 쓰지 않음 |
| `APP_TIMEZONE` | `Asia/Seoul` |
| `DATA_DIR` | `data` |
| `LLM_CALL_LIMIT` | 현재 0. 실호출 횟수 승인 후 정한 누적 상한으로 변경 |
| `LLM_MAX_INPUT_CHARS` | 12000 |
| `LLM_MAX_OUTPUT_TOKENS` | 2500 |
| `MAX_REJUDGEMENTS` | 2 |

설정 로더는 프로젝트 `.env`만 읽고, 상속된 Hermes/다른 프로젝트의 키로 자동 대체하지 않습니다. `.env.example`은 변수명과 안전한 예시만 가집니다. 실제 인증 JSON·토큰·원문·DB·캐시는 커밋하지 않습니다. 파일 상태 확인에서도 값은 출력하지 않습니다.

## 9. 화면 계약

사용 장면은 수업 공지를 보고 바로 일정을 정리하거나 대기 건을 처리하는 PC 브라우저입니다. 정보형 업무 화면으로, Streamlit 기본 컴포넌트와 읽기 좋은 폭을 유지합니다. 별도 이미지·장식·브랜딩 작업이나 캘린더 월간 화면은 만들지 않습니다.

- 첫 화면: 도구 목적 한 줄과 새 공지 입력, 기준 날짜, 분석 버튼. 연결/예산이 부족하면 버튼 옆에 구체적인 준비 항목을 표시합니다.
- 승인 대기: 목록에서 한 건을 선택하면 원문, AI 후보와 근거, 멈춘 이유, 충돌 시간, 승인 시 생성될 일정이 한 흐름으로 보입니다.
- 네 응답: 승인, 수정 후 승인, 반려 사유, 재판정 지시. 수정된 일시는 빈 값/추측 기본값으로 몰래 채우지 않습니다.
- 처리 기록: 실제 상태·일시·사용자 결정·Google 일정 링크. 화면을 다시 열어도 저장된 기록을 복원합니다.
- 연결 준비: 키/파일 준비 상태와 Google 로그인 진입점. 실제 키·토큰·인증 JSON을 화면에 표시하거나 업로드시키지 않습니다.
- 입력 보존: 조회·탭 이동은 제출이 아닙니다. 승인 폼은 표시한 버전에 묶고, 버전이 바뀌면 오래된 결정을 보내지 않습니다. 오류 시 사용자 입력과 수정안을 가능한 범위에서 유지합니다.
- 오류: ‘실패’ 한 단어 대신 문제와 가능한 다음 행동을 표시합니다. 공급자 원시 오류·민감값은 노출하지 않습니다.

오프라인 검사는 기존 백엔드 40개, 서비스 대역 AppTest 화면 15개, 실제 백엔드·SQLite·LangGraph를 붙인 소비자/가드 7개로 예상 62개와 실행 62개가 일치하고 모두 통과했습니다. 외부 제공자만 SDK/HTTP 또는 어댑터 대역이므로 실제 Google·모델 성공을 뜻하지 않습니다.

추가 검사에서 구조화 오류 객체의 화면 메시지 표시와 잘못된 시간대의 공개 오류 정규화를 RED→GREEN으로 보완했습니다. 정상 수정 승인→저장→ID readback의 소비 경로와 제공자 연결 차단은 검증용 추가 사례이며 모두 독립 RED부터 만들었다고 주장하지 않습니다. Windows AppTest는 stdlib socketpair가 쓰는 자기 소유 loopback IPC만 좁게 허용하고, 일반 직접 연결은 차단되는 음성 대조를 확인했습니다.

이후 승인받아 정상 앱 서버를 `127.0.0.1:8501`로 기동하고 새 격리 Chrome에서 네 탭·빈 대기/기록·미제출 입력 보존·연결 준비·실제 서비스 설정 재로드·좁은 창과 하단 스크롤의 8개 동작을 확인했습니다. 정상 factory이며 브라우저용 모의 서비스를 주입하지 않았고 분석/Google 연결은 누르지 않았습니다. 캡처 네 장을 시각 확인했으며 원문 날짜 입력은 위젯·글꼴 준비 뒤 캡처했습니다. 모델 요청·업무·전송 장부는 전후 모두 0입니다.

실제 대기 건의 수정·오류·기록 복원과 상세 자료의 가독성은 실연동 후 브라우저 검증 대상입니다. 390px 초기 화면에서 하단 사용량·설정 버튼은 스크롤해야 보이며, 실제 스크롤 후 확인했습니다. 큰 제목의 마지막 글자가 다음 줄로 넘어가는 미세 조판 한계는 보류합니다. 공개 서비스 함수·DTO 계약이나 앱 코드를 이번 확인에서 바꾸지는 않았습니다.

## 10. 의존성과 검증 게이트

`02_구현/의존성.txt`의 직접 의존성은 PyPI에서 확인한 버전으로 작성했습니다. 후속 승인 후 과제 전용 Python 3.12.10 환경에 총 86개를 설치하고 직접 버전 8개가 계획과 일치함을 확인했습니다. LangGraph와 SQLite 체크포인터는 각각 그래프와 영속 중단/재개를 담당합니다.[16][17]

Streamlit은 웹 화면, OpenAI SDK는 선택 모델 호출, Google 라이브러리 두 개는 Calendar API·OAuth를 담당합니다. python-dotenv는 `.env`, tzdata는 Windows의 시간대 자료를 제공합니다. LangChain 본체·MCP 서버·별도 JS 빌드 도구는 추가하지 않습니다.[18][19][20]

Google OAuth·dotenv·시간대 자료의 버전/지원 Python도 PyPI 메타데이터에서 확인했습니다. `uv pip check`는 `All installed packages are compatible`이었고, 실제 설치 버전 86개를 `02_구현/의존성_잠금.txt`에 기록했습니다. 이는 앱 기능이나 제공자 인증의 통과가 아닙니다.[21][22][23]

기초 검사에서는 메모리 SQLite의 실제 LangGraph를 `interrupt()`로 중단하고 `Command(resume="approve")`로 재개해 최종 상태와 노드 재실행 2회를 확인했습니다. 모델·Google 요청 없이 프레임워크 동작만 확인한 것입니다. 앱 본체의 영속화·승인 정책 검증은 후속 테스트입니다.

현재 전달하는 시험 실행 명령은 프로젝트 루트에서 `.venv/Scripts/python.exe 02_구현/테스트실행.py`입니다. 한국어 파일을 명시적으로 로드하고 고유 식별자·예상/실행 수·소스 안정성을 확인하며 `.local/최근_테스트.json`을 생성합니다. 원 인계서가 없어도 실행할 수 있습니다.

독립 정적 검토 원 판정은 Standards 통과 / Spec 수정 필요 2건(CAL-01 반복 오자동 처리, CAL-02 시간대 오류 계약)이었습니다. 원 보고서는 변경하지 않았습니다. 부모가 실제 실패를 재현하고 반복/교차일 가드와 APP_TIMEZONE을 명시하는 안전한 공개 오류 경계를 보완한 뒤 표적·양성 대조·전체 62개를 재검사했습니다. 이는 수정 후 별도 독립 재검토 통과라는 뜻이 아닙니다.

검증 순서:

1. 설치 전: 의존성 사전 해석, 실제 소비자/SDK 공개 인터페이스 확인, 비밀값 제외 검사.
2. 단위: 순수 규칙의 관찰된 RED→GREEN, 양성 대조·경계 사례. import 오류는 행동 RED로 세지 않음.
3. 격리 통합: 실제 임시 SQLite와 LangGraph + 외부 전송만 대역. 자동·승인·수정·반려·재판정·재시작 복원·중복·응답 불명·버전 경합 확인.
4. 연결부: SDK 실제 인자·payload·서버 반환 파싱을 주입 대역으로 확인. 외부 네트워크는 테스트에서 차단.
5. 후속 승인: 실제 모델의 구조화 출력과 실제 Google 로그인·조회·등록·재조회.
6. 로컬 기동·계정 준비 전 초기 8개 동작과 캡처 시각 확인 완료. 실제 대기 건·승인·오류·저장 기록의 브라우저 경로는 실연동 후 최종 소스에서 재검증.
7. 기준 후보 비교와 보고서는 실제 실행 기록에서 생성. 사용자 평가 정답·선택 이유·회고는 사용자 작성으로 구분.

기술 명세·코드·테스트·인증 파일 준비, 전용 환경 설치·오프라인 검사에 이어 로컬 서버 유지·격리 브라우저 확인도 승인됐습니다. 사용자 기존 탭은 건드리지 않고 시험 Chrome만 종료·프로필 정리했습니다. Google 로그인·모델과 캘린더 실호출은 별도 승인 전입니다. 문법·대역·초기 화면 통과는 실연동 완료가 아닙니다.
