# 일정 등록 에이전트 진행 현황

> 기준일: 2026-11-09 (Asia/Seoul)
> 현재 단계: 과제 폴더·요구사항·로컬 Git 준비 완료. Google 연결 준비 확인 안내와 외부 모델 비교 단계. 앱 구현은 아직 시작하지 않음.
> 요구사항 정본: [작업 명세서](<📘 작업 명세서.md>)

## 1. 작업 목적

공지문 → AI 일정 추출 → 위험 기준 검사 → 필요 시 사람 확인 → 실제 Google Calendar 등록.

새 캘린더 앱이나 로컬 일정 DB만으로 대체하지 않습니다. 성공의 최종 근거는 실제 Google 일정과 그 내용의 재조회입니다.

## 2. 사용자 확정·승인

- 노드 과제·실습으로 `02_노드실습/261109_일정등록_에이전트/`를 새로 사용.
- Google Calendar에 연결.
- 일정 추출용 AI는 외부 모델 API 사용. 제공자·모델·호출 상한은 아직 미선정.
- Google Cloud 프로젝트·OAuth 준비 여부는 모름. 설정 변경 없이 확인 방법부터 안내받기로 선택.
- 앱 내부 함수/API 방식. MCP 서버는 만들지 않음.
- `01_설계/📘 작업 명세서.md`, `01_설계/📋 진행 현황.md` 생성과 후속 현황 갱신 승인.
- 이 과제 폴더의 새 Git 저장소, `.gitignore`, `CHANGELOG.md`, 검증 단위별 로컬 커밋 승인.
- GitHub 저장소 생성·push·태그·공개 배포는 아직 승인하지 않음.

## 3. 이번에 확인한 사실

| 항목 | 확인 결과 | 증거의 한계 |
|---|---|---|
| 수업 요구 | 환불 외 주제, 외부 실행 전 멈춤·재개, 자동 처리, 승인 기준 두 가지 이상, 웹 데모·보고서 | 저장된 원문 확인이며 LMS를 새로 조작하지 않음 |
| 작업 경로 | 생성 전 해당 폴더 없음, 상위 경로 존재 | 이름 충돌 확인일 뿐 앱 기능 증거가 아님 |
| 저장소 격리 | 생성 전 상위 경로에 `.git` 없음 | 새 단독 저장소로 준비할 수 있다는 사실만 확인 |
| Git 실행 파일 | `git version 2.53.0.windows.3` | 과제 코드나 인증이 준비됐다는 뜻이 아님 |
| Google 공식 API | quickstart·events.insert·인증 범위 본문 HTTP 200 | 계정 인증·실제 조회·일정 생성은 하지 않음 |
| LangGraph 공식 중단 동작 | 체크포인터·thread_id·재개 시 노드 재실행 본문 HTTP 200 | 패키지 설치·예제 실행은 하지 않음 |
| 외부 모델 후보 | `gpt-6-luna`, `gemini-3.5-flash-lite`의 공식 모델·가격 본문 HTTP 200 | 모델 선택·계정 접근·실제 추출·청구액은 미검증 |

웹 추출 도구는 현재 백엔드가 본문 추출을 지원하지 않아 실패했습니다. 같은 공식 URL을 Python 표준 HTTP 요청으로 읽어 본문을 확인했습니다. 실패를 원문 확인 성공으로 기록하지 않습니다.

비용·무료 조건은 작업 명세서 9절에 기록했습니다. 기존 2026-11-05 OpenAI 무료 토큰 안내를 먼저 읽었으며 당일 도움말 직접 접속은 HTTP 403, 검색 결과는 제한된 발췌였습니다. 계정 설정이나 공유 활성화 여부는 확인하지 않았습니다.

문서 준비의 첫 로컬 커밋은 `e3974a3`이며 당시 승인된 네 파일의 정확한 커밋 목록·작업 트리 clean·원격 없음·비밀값 검사 PASS를 확인했습니다. 이것은 앱 실행이나 사용자 데이터의 백업 증거가 아닙니다.

## 5. 지금 허용되지 않은 작업

패키지 설치, 앱 구현·기동, 모델 호출, 다른 프로젝트의 인증 파일 열람·복사, Google Cloud 리소스 변경, 계정 권한 부여, 캘린더 조회·일정 생성·수정·삭제·초대 발송은 이번 폴더·문서·Git 승인에 포함되지 않습니다.

외부 모델 API를 쓰기로 했지만 아직 호출 권한·횟수를 승인받은 것은 아닙니다. 제공자를 확정하지 않은 채 모델을 호출하거나 기존 Hermes 구독 인증을 이 앱에서 재사용하지 않습니다.

## 6. 다음 구체적 단계

사용자에게 Google Cloud Console의 기존 프로젝트, 사용 설정된 Google Calendar API, Google Auth platform의 OAuth 클라이언트 존재·유형을 읽기 전용으로 확인하는 절차를 안내합니다. 설정 생성·변경이나 인증 JSON 다운로드를 시키지 않습니다. 사용자는 이 준비 상태만 알려주면 되며 인증값은 채팅으로 받지 않습니다.

모델은 공식 표준 요금과 구조화 출력 지원을 근거로 `gpt-6-luna`를 초기 후보로 권고할 수 있습니다. 아직 사용자가 선택하지 않았으므로 설정에 확정 모델로 넣지 않습니다. Gemini 대안·무료 조건·단순 계산 예시는 작업 명세서 9절을 참고합니다. 권고는 실제 추출 품질 검증이 아닙니다.

연결 대상으로 기본 캘린더를 쓸지, Google Calendar 안의 별도 과제용 캘린더를 쓸지는 아직 미정입니다. 후자는 새 캘린더 앱 개발이 아니라 같은 Google 서비스 안의 분리된 일정 묶음입니다. 어느 쪽도 임의 생성하지 않습니다.

그다음 실제 입력 예시, 승인 기준 두 가지, 사용자 담당 판단, 기술 명세서와 구현 범위를 확정합니다. 모델·계정 준비가 안 됐다는 이유로 이미 합의한 요구사항을 처음부터 다시 인터뷰하지 않습니다.

## 7. 주요 결정 이유·한계·보류

- 기존 프로젝트에 억지로 붙이지 않고 독립 과제로 분리: 기존 기능의 범위와 회귀 부담을 늘리지 않기 위함.
- Google Calendar 실연동 유지: 실제로 쓸 수 있는 보조 에이전트를 만들려는 사용자 목표.
- 앱 내부 함수/API: 이번 과제에 별도 MCP 서버 운영을 추가하지 않음.
- 사람 검토 후보는 일시 정보 모호함과 일정 충돌. 아직 사용자 확정이나 실제 검증 결과가 아님.
- 원문 근거·코드 검증·사람 결정·외부 반영 기록을 구분. LLM의 확신도만으로 안전을 보장하지 않음.
- 기존 일정 수정·삭제, 참석자 초대, 메일·단체방 자동 수집, 공개 호스팅은 현재 범위 밖.
- 사용자 선택 이유·평가 정답·회고를 에이전트가 사용자 의견으로 임의 작성하지 않음.
- 별도 기술 명세서는 실제 연동 경계를 확인하고 생성 승인을 받은 뒤 작성.
- 초기 전체 예상 1~3시간은 추정이며, 인증 설정 대기는 별도. 구현 소요시간 실측은 아직 없음.

## 8. 재개 방법

프로젝트 루트에서 작업 명세서·이 현황·CHANGELOG와 실제 파일을 함께 확인합니다. Git은 승인된 로컬 방식대로 사용하되 기존 변경을 먼저 구분합니다. 아직 없는 앱을 완료된 것으로 해석하거나, 문서의 시험 계획을 실행 증거로 취급하지 않습니다.
